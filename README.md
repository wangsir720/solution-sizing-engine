# 行业解决方案测算引擎（Solution Sizing Engine）

> 输入客户的业务场景参数，输出可直接进方案文档的计算依据：算力配置清单、三年 TCO、
> 统建迁移路径、交付运营指标基线、业务价值测算表。
>
> **数据为公开信息与行业典型值，非真实交付项目。** 全部单价可回溯到公开标价页。

零第三方依赖，`git clone` 后直接跑。

---

## 1. 为什么做这个

行业解决方案的测算环节有三个老问题：

1. **算力配置靠拍脑袋** —— 输出「3.5 张卡」这种数字，评审时一问就露馅，因为真实采购只能按整机算。
2. **成本说不清来源** —— 报价单里只有总价，评审方无法验证单价从哪来，于是整份测算的可信度归零。
3. **迁移方案只写「分 3 波次」** —— 没有影响面、没有回退条件、没有割接检查清单，
   真出事时拿不出该做什么。

这个工具把这三件事变成可复算的代码：**卡数必须向上取整到整机粒度**、
**每行成本都带单价来源与抓取日期**、**每个迁移波次都必须给出四要素**。

## 2. 覆盖哪些问题

| 能力 | 输入 | 输出 | 关键约束 |
|---|---|---|---|
| 算力配置测算 | 业务参数 JSON | GPU/通用节点数、存储容量、带宽峰值 | 卡数向上取整到整机粒度，上浮量显式标注 |
| 三年 TCO | 配置清单 | 成本明细表（每行带单价来源） | 缺公开单价时进「未计入项」，不用 0 元凑总额 |
| 统建迁移路径 | 场景规模 + 配置 | 5 个波次 × 四要素 | 双写窗口是最硬的时间约束，超窗回退成本剧增 |
| 交付运营指标 | 服务等级目标 | 9 项指标（定义/目标/测量/依据） | 自定口径必须标注，不冒充国标要求 |
| 业务价值测算 | 场景 + TCO | 可算项给公式，不可算项列所需输入 | 不输出「提升 X%」这类无口径结论 |

## 3. 数据源与合规边界

| 数据 | 来源 | 说明 |
|---|---|---|
| GPU 实例月价 | 腾讯云官方计费文档 | 包年包月价，按 SKU 记录，含来源 URL 与抓取日期 |
| 存储分层月价 | 腾讯云官方价格总览 | 高性能/通用型 SSD/快照，含来源 URL |
| 公网带宽阶梯 | 腾讯云官方定价页 | ≤2 / 2–5 / >5 Mbps 三档，含来源 URL |
| 场景参数 | `data/scenarios/*.json` | 行业典型值，**非真实客户需求** |
| 性能假设 | `data/assumptions.md` | 逐条登记假设编号，注明依据或标注「占位待实测替换」 |

**明确不含**：真实客户名称、合同金额、账号凭据、内部报价、任何客户业务数据。

## 4. 方法

```
data/scenarios/<场景>.json
        │
        ├─ pricing.py ──── 读 data/pricing/*.csv，校验来源字段，价格与逻辑彻底分离
        │
        ├─ sizing.py ───── 业务参数 → 配置清单（每项带 trace 推导链）
        │      │
        │      ├─ tco.py ─────── 配置清单 → 三年 TCO（每行带 unit_price_source）
        │      ├─ migration.py  配置清单 → 5 波次迁移方案（四要素齐全）
        │      ├─ ops_metrics.py 场景 → 9 项运营指标（口径逐条标注依据）
        │      └─ value_model.py 场景 + TCO → 业务价值表（公式可复算）
        │
        └─ cli.py ──────── 渲染 output/<场景>/solution_package.md + CSV
```

价格表外置为 CSV 是有意的结构选择：改价不用改代码，
价目表与计算逻辑分离后，任何一行的金额都能顺着 `unit_price_source` 追回到原始页面。

## 5. 快速开始

环境要求：Python 3.10+（验证于 3.12.8 / Windows）。**无需 pip install 任何运行时依赖。**

```bash
# 列出可用场景
python -m src.cli --list

# 生成单个场景的方案包
python -m src.cli --scenario gov_video_surveillance

# 一次生成全部场景
python -m src.cli --all

# 跑测试
pip install pytest
python -m pytest -q
```

生成物落在 `output/<场景编号>/`：

| 文件 | 内容 |
|---|---|
| `solution_package.md` | 完整方案包草稿（7 章，含免责声明与边界声明） |
| `tco_breakdown.csv` | TCO 明细，含单价来源与推导链，可直接贴进标书 |
| `migration_checklist.csv` | 逐波次割接检查清单，可直接转成实施任务表 |
| `result.json` | 全量结构化结果，便于接入其他系统或做二次分析 |

## 7. 已知局限

| # | 局限 | 影响 | 补齐方式 |
|---|---|---|---|
| 1 | 通用计算节点（CPU）无公开单价表 | 该科目未计入总额 | 官方仅提供在线价格计算器，需按实际规格取当日报价后手工补入 |
| 2 | 冷数据无公开归档档位价 | 冷存储按高性能云硬盘计，金额偏高 | 取到归档类存储公开报价后补进 `data/pricing/storage_tier.csv` |
| 3 | 推理吞吐、转码路数、单节点 QPS 为占位值 | 卡数与节点数是量级估算，不是实测 | 必须用真实模型与真实请求压测替换（`data/assumptions.md` A-03 / A-08） |
| 4 | 成本模型不含税、不含商务折扣 | 实际采购价高于本表合计 | 以采购当日官方报价与合同为准 |
| 5 | 迁移波次按分层固定，未做代码依赖扫描 | 真实波次划分可能不同 | 须以实际系统的依赖分析结果重划 |
| 6 | 不含实施与迁移人力成本 | TCO 只覆盖云资源侧 | 人力按项目单独核算 |
| 7 | 场景参数为行业典型值 | 结论随场景变化 | 拿到真实需求后替换 JSON 重跑即可，代码无需改动 |

第 3 条是本项目最大的短板，明确写在这里而不是藏起来：**算力测算的精度取决于那三个
占位吞吐值**，它们在真实项目里必须由压测数据替换。换句话说，这个工具验证的是
**测算方法与成本模型的可追溯性**，不是某个具体场景的最优配置。

## 8. 声明

本仓库不包含任何真实客户名称、合同金额、账号凭据、内部报价或客户业务数据。
场景参数为行业典型值，价目表取自公开标价页，假设逐条登记在 `data/assumptions.md`。
本项目与任何云厂商无隶属或合作关系，文中出现的厂商名称与产品名称仅为价格来源标注。
